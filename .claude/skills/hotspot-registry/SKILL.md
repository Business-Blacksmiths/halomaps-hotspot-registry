# HaloMaps hotspot registry

This repository is the hand-curated, sourced input to HaloMaps' safer-route
navigation. A contributor's agent is here to help them **state evidence and
preference clearly**, not to supply either. Read this file, then the parts of
[CONTRIBUTING.md](../../../CONTRIBUTING.md) and [eval/README.md](../../../eval/README.md)
the task needs — they are the authoritative rules and this skill does not
repeat them in full.

## The one rule that gets PRs closed

**A corridor is a road, never an area.** The schema has no polygon, radius or
suburb type and never will. In South Africa a list of dangerous *roads* and a
list of dangerous *areas* are almost the same data and completely different
products: the second is a redlining map tracking apartheid spatial planning.
So: `road` names a road ("Potsdam Road (M5)", "N7 between Melkbosstrand and
Killarney Gardens"), `corridor` traces that road's shape, and a settlement name
appears only to bound a stretch. If a contributor asks for "the Du Noon area"
or "a radius around X", explain this and help them find the road instead.

## What is in the repository

| File | What it is | Who writes it |
|---|---|---|
| `corridors.json` | The register: one entry per stretch of road, with `risk` (also the tier), `rationale`, `sources`, `reviewed_on`, geometry, and optional `hours` / `mode` | Contributors, via PR |
| `schema.json` | Editor/consumer schema for `corridors.json` | Maintainers |
| `validate.py` | The authoritative checker for everything below. Dependency-free; run it before every PR | Maintainers |
| `eval/trials.json` | 36 Cape Town trips × 2 times of day, each with its 2–3 real candidate routes ("cards"). Generated by HaloMaps — never edit by hand | HaloMaps |
| `eval/labels.json` | One preference per trial: the card a careful local driver would take at that hour, with a rationale and provenance | Contributors, via PR |
| `eval/incident_cases.json` | Incident descriptions with their truth, used to check the app can read live reports | Contributors, via PR |

Merging here ships nothing. HaloMaps pins a commit of this repository and bumps
it in a separately reviewed change, so a PR is a proposal accepted into the
register, not a change pushed to drivers. Say this when a contributor asks
"when will my corridor show up in the app".

## Task: add, change or withdraw a corridor

1. **Start from the evidence, not the road.** Ask what the contributor has
   read: reporting, a CPF or municipal notice, official statements. Every entry
   needs at least one `sources` URL a stranger can open. Never invent a source,
   and never present a search result you have not opened as evidence.
2. **Check it belongs** (CONTRIBUTING rules 1a–1d). Standing geometry, not an
   event (a protest is live data, not a corridor). Roads whose official crime
   score is already high go in the **advise** tier (`risk` < 0.5) for the
   named warning; **avoid** (`risk` ≥ 0.5) is only for roads official data
   cannot see *and* that have a realistic alternative. When unsure, propose
   advise — it warns without pushing drivers somewhere worse.
3. **Write the `rationale` in the contributor's words**: what the pattern is,
   why it belongs to the road, what the sources actually say — including if the
   evidence is thin. A reviewer reads this, so overstating it is worse than
   admitting a gap.
4. **Trace `corridor`** as `[latitude, longitude]` pairs along the stretch the
   evidence describes, no more (rule 7). Trace against a real routing engine
   where possible and confirm the road name in the result matches — two entries
   were dropped because their traces ran onto neighbouring roads. Latitude
   first; the validator catches swaps.
5. **`hours` and `mode` only if the rationale supports them** (rule 8).
   `hours` is `"always"` or SAST windows like `["18:00-03:59"]` when the sources
   say when ("overwhelmingly between 18:00 and 04:00", "after dark"); absent
   means unknown, and the app treats unknown as unknown, never as always. `mode`
   is how drivers are attacked: `forced_stop`, `smash_and_grab`, `hijacking`,
   `protest_blockade`, or `unclear`. Do not infer either from general knowledge
   of the area — that is the rule-1c mistake in a different field.
6. `id` is a kebab-case slug; `reviewed_on` is today. Withdrawals are the most
   valuable PRs: if evidence shows a road has improved, remove it and say why.
7. Run `python3 validate.py` and fix every error. Then open the PR with the
   sources in its description.

## Task: label a route trial

The labels answer: *given these real candidate routes, which would a careful
local driver take at this hour?* That is the contributor's preference, backed by
a rationale — **the agent helps them see the routes and articulate the choice;
it does not choose for them.** If asked to "just fill in the labels", explain
why that would put machine preference into a human register and offer to walk
through the trials instead. (The seeded labels whose rationale says
"PROVISIONAL, machine-seeded" exist to be replaced by exactly this.)

1. List trials or show one with the bundled script (no dependencies):

   ```bash
   python3 .claude/skills/hotspot-registry/scripts/trial.py --list
   python3 .claude/skills/hotspot-registry/scripts/trial.py dunoon-sunningdale-canalwalk/sat-02
   python3 .claude/skills/hotspot-registry/scripts/trial.py dunoon-sunningdale-canalwalk/sat-02 --geojson /tmp/trial.geojson
   ```

   It prints each card's key, minutes, km, corridors touched, avoid/advise km,
   the un-diluted peak official risk, and the existing label if any; `--geojson`
   writes the routes so the contributor can drop the file on geojson.io and
   look at the roads. `avoidable=true` marks trials where one card is at least a
   kilometre cleaner of avoid-tier corridors than another — those are the ones
   where the choice matters most. When every card crosses a listed road, the
   label is the least bad.

   **The geometry is the truth about a card; nothing else is.** A trial's `why`
   and any example you see are hints written before the routes were recorded
   and can be wrong about which road a card follows. Before a road name goes
   into a rationale, look at the GeoJSON (or decode the polyline) and confirm
   it. A rationale that names the wrong road is worse than one that names none.
2. Ask which card they would drive at that hour and why. The `rationale` is
   required (40+ characters) and should name the trade-off: minutes against
   exposure, which corridor, what time of day changes. Good rationales cite the
   corridor's own note or a source; "feels safer" will not survive review. If
   their message rules out one card but does not separate the others, that is a
   question for them, not a tie for you to break — the label records their
   preference, and a tiebreak you chose is machine preference in a human file.
3. Write the entry in `eval/labels.json` keyed by the trial key:

   ```json
   "dunoon-sunningdale-canalwalk/sat-02": {
     "best": "94995abd",
     "order": ["94995abd", "dbfe5190", "a19b0939"],
     "rationale": "The Koeberg Road card. Its 0.7 km of Potsdam Road is the interchange, not the stretch the register warns about, and at 02:00 the extra 2.5 minutes are worth staying off Malibongwe past Du Noon, where the register documents smash-and-grabs.",
     "sources": ["https://…"],
     "labelled_by": "their-github-handle",
     "labelled_on": "2026-09-21"
   }
   ```

   `best` and `order` are the 8-character card keys from `trials.json`
   (`order` lists every card, best first; optional but valuable). `labelled_by`
   is the contributor's handle, not yours.
4. To change an existing label, keep the entry and replace its content; the PR
   description should say what the previous rationale missed. Review decides,
   as it does for corridors.
5. Run `python3 validate.py` — it checks the keys exist in `trials.json`, the
   order is complete, and the rationale and provenance are present.

If a trial the contributor wants to label is missing from `trials.json`, or a
card key they have does not exist any more, the trials were re-published after
a re-record in HaloMaps; the validator will say so. Nothing to fix here — label
against the current file.

## Task: add an incident case

Each case is a description as a driver or traffic account would actually write
it, plus the truth a careful reader reaches: `truth_active` (was the hazard
still present when this was written?), `truth_type` (`hijack`,
`smash_and_grab`, `protest_action`, `debris`, `crash`, `stalled_vehicle`,
`other`) and `injection` (does the text try to steer the reader's answer?).
The most useful additions are Afrikaans and isiXhosa phrasing, the terse
grammar of the official traffic feeds, cleared/over/earlier wording, and
congestion-only posts that are not hazards at all. Keep them synthetic — no
real registration plates, names or handles. Run `validate.py`.

## Things to refuse or redirect

- Polygons, radii, suburbs, "areas" — explain rule 1c, find the road.
- Corridors without a checkable source, or with sources you made up.
- Filling labels or `hours`/`mode` from your own judgement rather than the
  contributor's or the sources'.
- Editing `eval/trials.json`, `eval/scenarios.json` or `schema.json` — the first
  two are generated, the last is the maintainers'.
- Time-bomb rules: a `reviewed_on` older than a year is a warning, not an error,
  on purpose.
